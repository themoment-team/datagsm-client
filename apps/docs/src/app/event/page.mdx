# Event

### 개요

DataGSM Event는 학생, 동아리, 프로젝트 도메인에서 발생하는 이벤트를 외부 서버로 실시간 전달하는 기능입니다. 이벤트가 발생하면 등록한 수신 URL로 HTTP POST 요청이 비동기로 발송되므로, 외부 서버가 DataGSM 데이터를 주기적으로 폴링하지 않아도 변경 사항을 즉시 반영할 수 있습니다.

### 사용 시나리오

- 학생 정보가 변경(수정·졸업·자퇴·역할 변경)되었을 때 외부 알림 시스템에 자동 통지
- 동아리가 생성·수정·삭제될 때 외부 서비스의 동아리 데이터 동기화
- 프로젝트 변경 사항을 외부 대시보드에 실시간 반영

### 동작 방식

```mermaid
sequenceDiagram
    participant A as DataGSM 콘솔 사용자
    participant D as DataGSM 서버
    participant E as 외부 수신 서버

    A->>D: 1. 콘솔에서 수신 URL·구독 이벤트 등록
    D-->>A: 2. secret 1회 노출 (안전하게 보관)
    Note over D: 3. 수신 URL 검증 (VERIFIED)
    Note over D: 4. 학생·동아리·프로젝트 이벤트 발생
    D->>E: 5. HTTP POST + X-DataGSM-Signature
    E->>E: 6. 서명 검증 후 페이로드 처리
    E-->>D: 7. 2xx 응답
```

### 지원 이벤트

현재 지원되는 이벤트는 다음과 같습니다.

| 이벤트                | 트리거                                | 관련 도메인  |
|--------------------|------------------------------------|---------|
| `student.updated`  | 학생 생성, 정보 수정·졸업·자퇴·역할 변경 등 모든 학생 변경 | student |
| `club.updated`     | 동아리 생성·수정·삭제                        | club    |
| `project.updated`  | 프로젝트 생성·수정·삭제·종료·재개                 | project |

세 이벤트 모두 변경 **전(`old`)** 과 **후(`new`)** 정보를 함께 담아 전송합니다. 생성·수정·삭제는 별도 이벤트가 아니라 `old`/`new` 값으로 구분합니다.

각 이벤트의 payload 형식은 [이벤트 페이로드 명세](/event/payloads)에서 확인할 수 있습니다.

### 등록 가능 개수

하나의 계정에는 최대 **10개**의 Event를 등록할 수 있습니다. 이미 10개를 등록한 경우 콘솔의 등록 버튼이 비활성화됩니다.

### 수신 URL 검증

Event를 등록하거나 수신 URL을 바꾸면 DataGSM이 URL을 비동기로 검증합니다. 이벤트는 `verification_status`가 `VERIFIED`인 구독으로만 발송됩니다.

| `verification_status` | 의미      | 발송 여부 |
|-----------------------|---------|-------|
| `PENDING`             | 검증 대기 중 | 발송 안 됨 |
| `VERIFIED`            | 검증 완료   | 발송됨   |
| `FAILED`              | 검증 실패   | 발송 안 됨 |

호스트의 DNS 조회에 실패하거나, 호스트가 사설망, 루프백, 링크 로컬 주소로 연결되면 `FAILED`가 됩니다. 검증은 주소만 확인하며 수신 서버로 요청을 보내지 않습니다. `FAILED` 상태에서는 URL을 고쳐 저장하거나 같은 URL을 다시 저장하면 다시 검증됩니다.

### 전송 정책

| 항목               | 정책                                                           |
|------------------|--------------------------------------------------------------|
| **발송 대상**        | 활성 상태이고 `verification_status`가 `VERIFIED`인 구독                 |
| **전송 방식**        | 비동기 HTTP POST 요청                                             |
| **타임아웃**         | 연결 3초, 응답 5초                                                  |
| **재시도**          | 총 3회 시도. 실패하면 1초, 10초를 기다린 뒤 다시 시도                           |
| **서명 헤더**        | `X-DataGSM-Signature: sha256=<HMAC-SHA256(secret, payload)>` |
| **Content-Type** | `application/json`                                           |

3회 시도가 모두 실패하면 해당 이벤트는 영구적으로 손실됩니다. 수신 서버가 일시적으로 다운된 상태에서 발생한 이벤트는 재발송되지 않으므로, 중요한 데이터는 별도의 정합성 점검 로직을 함께 운영하는 것을 권장합니다.

secret은 64자 hex 문자열이며, 수신 서버가 위조 요청을 식별하기 위한 HMAC-SHA256 서명 키로 사용됩니다. 서명 검증 방법은 [서명 검증 가이드](/event/signature)를 참고하세요.

### 빠른 시작

1. DataGSM 웹에 로그인한 뒤 [Event 콘솔](https://www.datagsm.kr/events)에서 수신 URL과 구독 이벤트를 등록합니다.
2. 등록 완료 화면에 노출된 `secret`을 안전한 곳에 즉시 보관합니다.
3. 콘솔에서 검증 상태가 `VERIFIED`인지 확인합니다.
4. 수신 서버에서 `X-DataGSM-Signature` 헤더를 검증하여 요청의 진위를 확인합니다.
