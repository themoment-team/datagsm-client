# DataGSM OpenAPI SDK Python

### 개요

**DataGSM OpenAPI SDK Python**은 DataGSM API를 Python 애플리케이션에서 쉽고 안전하게 사용할 수 있도록 설계된 공식 클라이언트 SDK입니다.

이 SDK를 사용하면 복잡한 HTTP 요청을 직접 작성할 필요 없이, 타입 안전한 인터페이스를 통해 학생, 동아리, 프로젝트, NEIS 데이터를 조회하고 학생, 동아리, 프로젝트 데이터를 생성, 수정할 수 있습니다. 모든 API는 동기 방식이며 async API는 없습니다.

### 주요 특징

| 특징                 | 설명                                            |
|--------------------|-----------------------------------------------|
| **타입 안전성**         | 타입 힌트를 통해 IDE 자동완성과 정적 타입 검사를 지원합니다.          |
| **Pydantic 검증**    | Pydantic v2를 통한 자동 데이터 검증 및 직렬화를 제공합니다.       |
| **dataclass 기반**   | 직관적이고 유연한 API 요청 구성을 지원합니다.                   |
| **자동 리소스 관리**      | Context manager를 통해 리소스 누수를 자동으로 방지합니다.       |
| **구체적인 예외 처리**     | HTTP 상태 코드별 전용 예외 타입을 제공하여 정확한 에러 핸들링이 가능합니다. |
| **검증된 HTTP 클라이언트** | httpx 기반으로 안정적이고 효율적인 통신을 보장합니다.              |

## 빠른 시작

### 1. 클라이언트 초기화

먼저 `DataGsmClient` 인스턴스를 생성합니다. API 키는 필수 파라미터입니다.

```python
from datagsm_openapi import DataGsmClient

# 기본 설정으로 클라이언트 생성
with DataGsmClient(api_key="your-api-key-here") as client:
    # API 사용
    pass

# 커스텀 Base URL 설정 (선택사항)
with DataGsmClient(
    api_key="your-api-key-here",
    base_url="https://openapi.datagsm.kr",
    timeout=10.0,  # 요청 타임아웃(초), 기본값 30.0
) as client:
    # API 사용
    pass
```

`with`문을 쓰지 않는다면 사용이 끝난 뒤 `client.close()`를 호출하세요.

### 2. API 호출 예제

클라이언트를 생성한 후, 다양한 API를 호출할 수 있습니다.

#### 학생 데이터 조회

```python
from datagsm_openapi import DataGsmClient
from datagsm_openapi.api.student import StudentRequest
from datagsm_openapi.models import Major

# 요청 파라미터 설정
request = StudentRequest(
    grade=1,  # 1학년
    class_num=1,  # 1반
    major=Major.SW_DEVELOPMENT,  # 소프트웨어개발과
    github_id="octocat",  # GitHub ID
    page=0,  # 첫 번째 페이지
    size=50  # 페이지당 50명
)

with DataGsmClient(api_key="your-api-key") as client:
    # API 호출
    response = client.students.get_students(request)

    # 결과 처리
    for student in response.students:
        print(f"{student.name} - {student.email}")
```

#### 급식 데이터 조회

```python
from datagsm_openapi import DataGsmClient
from datagsm_openapi.api.neis import MealRequest
from datetime import date

# 오늘 날짜의 급식 조회
request = MealRequest(date=date.today())

with DataGsmClient(api_key="your-api-key") as client:
    meals = client.neis.get_meals(request)

    # 급식 데이터 출력
    for meal in meals:
        print(f"{meal.meal_type}:")
        for menu in meal.meal_menu:
            print(f" - {menu}")
```

## API 레퍼런스

SDK는 다음과 같은 API 클라이언트를 제공합니다. 요청 클래스와 예외는 `datagsm_openapi`에서, enum과 응답 모델은 `datagsm_openapi.models`에서 가져옵니다.

쓰기 메서드를 쓰려면 API 키에 해당 쓰기 권한 범위(`student:write`, `club:write`, `project:write`)가 있어야 합니다. 이 범위는 관리자 계정만 발급할 수 있습니다.

### 학생 API

**`client.students`** - 학생 데이터 조회, 생성, 수정

| 메서드                                 | 설명                                | 반환 타입              |
|-------------------------------------|-----------------------------------|--------------------|
| `get_students(request=None)`        | 조건에 맞는 학생 목록 조회                   | `StudentResponse`  |
| `get_student(student_id)`           | 학생 단건 조회. 졸업생, 자퇴생 포함, 없으면 `None` | `Optional[Student]` |
| `create_student(request)`           | 학생 생성                             | `Student`          |
| `update_student(student_id, request)` | 학생 수정 (전체 교체)                     | `Student`          |

```python
# 학생 목록 조회
students = client.students.get_students(request)

# 특정 학생 조회
student = client.students.get_student(1)
```

`StudentRequest`의 필드는 다음과 같습니다. 기본값은 `page` 0, `size` 300, `sort_direction` `ASC`이며 `size`는 최대 1000입니다.

| 필드                                  | 타입                     | 설명                 |
|-------------------------------------|------------------------|--------------------|
| `student_id`                        | `int`                  | 학생 ID              |
| `name`, `email`                     | `str`                  | 이름, 이메일            |
| `grade`, `class_num`, `number`      | `int`                  | 학년, 반, 번호          |
| `sex`, `role`                       | `Sex`, `StudentRole`   | 성별, 역할             |
| `dormitory_room`                    | `int`                  | 기숙사 호실             |
| `specialty`, `major`                | `str`, `Major`         | 전공, 학과             |
| `github_id`                         | `str`                  | GitHub 아이디 (부분 일치) |
| `include_graduates`, `include_withdrawn` | `bool`            | 졸업생, 자퇴생 포함 여부     |
| `only_enrolled`                     | `bool`                 | 재학생만 조회            |
| `page`, `size`                      | `int`                  | 페이지 번호, 페이지 크기     |
| `sort_by`, `sort_direction`         | `StudentSortBy`, `SortDirection` | 정렬 기준, 정렬 방향 |

enum 필드에는 문자열이 아니라 enum 값을 넘기세요. `major="SW_DEVELOPMENT"`처럼 문자열을 넘기면 `AttributeError`가 발생합니다.

`CreateStudentRequest`는 `name`, `sex`, `email`이 필수입니다. 재학생은 `grade`, `class_num`, `number`도 필요합니다. `UpdateStudentRequest`는 전체 교체 방식이라 `name`, `sex`, `email`, `grade`, `class_num`, `number`, `role`이 필수이고, 생략한 선택 필드(`dormitory_room_number`, `major_club_id`, `autonomous_club_id`, `specialty`, `github_id`)는 비워집니다. 졸업생과 자퇴생은 수정할 수 없고 `role`을 `GRADUATE`, `WITHDRAWN`으로 바꿀 수 없습니다.

```python
from datagsm_openapi import CreateStudentRequest, UpdateStudentRequest
from datagsm_openapi.models import Sex, StudentRole

created = client.students.create_student(
    CreateStudentRequest(
        name="홍길동",
        sex=Sex.MAN,
        email="s25001@gsm.hs.kr",
        grade=1,
        class_num=1,
        number=1,
    )
)

client.students.update_student(
    created.id,
    UpdateStudentRequest(
        name="홍길동",
        sex=Sex.MAN,
        email="s25001@gsm.hs.kr",
        grade=1,
        class_num=1,
        number=2,
        role=StudentRole.GENERAL_STUDENT,
    ),
)
```

### 동아리 API

**`client.clubs`** - 동아리 데이터 조회, 생성, 수정, 삭제

| 메서드                           | 설명                     | 반환 타입                |
|-------------------------------|------------------------|----------------------|
| `get_clubs(request=None)`     | 조건에 맞는 동아리 목록 조회       | `ClubResponse`       |
| `get_club(club_id)`           | 동아리 단건 조회. 없으면 `None`  | `Optional[ClubDetail]` |
| `create_club(request)`        | 동아리 생성                 | `ClubDetail`         |
| `update_club(club_id, request)` | 동아리 수정 (전체 교체)         | `ClubDetail`         |
| `delete_club(club_id)`        | 동아리 삭제                 | `None`               |

```python
from datagsm_openapi import ClubRequest, ClubWriteRequest
from datagsm_openapi.models import ClubStatus, ClubType

# 동아리 목록 조회
clubs = client.clubs.get_clubs(ClubRequest(status=ClubStatus.ACTIVE))

# 특정 동아리 조회
club = client.clubs.get_club(1)

# 동아리 생성
created = client.clubs.create_club(
    ClubWriteRequest(
        name="SW개발동아리",
        type=ClubType.MAJOR_CLUB,
        founded_year=2022,
        status=ClubStatus.ACTIVE,
        leader_id=1,
        participant_ids=[2, 3],
    )
)
```

`ClubRequest`의 필드는 `club_id`, `club_name`, `club_type`, `status`, `founded_year`, `page`, `size`, `include_leader_in_participants`, `sort_by`, `sort_direction`입니다. 기본값은 `page` 0, `size` 100, `include_leader_in_participants` `False`, `sort_direction` `ASC`입니다.

`ClubWriteRequest`는 `name`, `type`, `founded_year`, `status`가 필수입니다. 운영 중인 동아리에는 부장이나 부원이 한 명 이상 필요합니다. 폐지(`ABOLISHED`) 동아리는 부장과 부원 없이 `abolished_year`를 함께 보냅니다.

### 프로젝트 API

**`client.projects`** - 프로젝트 데이터 조회, 생성, 수정, 삭제, 종료, 재개

| 메서드                                 | 설명                                     | 반환 타입             |
|-------------------------------------|----------------------------------------|-------------------|
| `get_projects(request=None)`        | 조건에 맞는 프로젝트 목록 조회                      | `ProjectResponse` |
| `get_project(project_id)`           | 프로젝트 단건 조회. `ACTIVE`, `ENDED`를 모두 찾고 없으면 `None` | `Optional[Project]` |
| `create_project(request)`           | 프로젝트 생성                                | `Project`         |
| `update_project(project_id, request)` | 프로젝트 수정. 운영 상태는 바뀌지 않음             | `Project`         |
| `delete_project(project_id)`        | 프로젝트 삭제                                | `None`            |
| `end_project(project_id, request)`  | 프로젝트 종료                                | `None`            |
| `reactivate_project(project_id)`    | 종료된 프로젝트 재개                            | `None`            |

```python
from datagsm_openapi import EndProjectRequest, ProjectRequest, ProjectWriteRequest
from datagsm_openapi.models import ProjectCategory, ProjectStatus

# 종료된 팀 프로젝트 조회
projects = client.projects.get_projects(
    ProjectRequest(status=ProjectStatus.ENDED, category=ProjectCategory.TEAM)
)

# 특정 프로젝트 조회
project = client.projects.get_project(1)

# 프로젝트 생성
created = client.projects.create_project(
    ProjectWriteRequest(
        name="DataGSM",
        description="학교 데이터를 제공하는 API 서비스",
        start_year=2024,
        club_id=1,
        participant_ids=[1, 2],
        categories=[ProjectCategory.TEAM, ProjectCategory.CLUB],
    )
)

# 카테고리를 모두 해제. 유지할 값은 함께 보냅니다
client.projects.update_project(
    created.id,
    ProjectWriteRequest(
        name="DataGSM",
        description="설명 수정",
        start_year=2024,
        club_id=1,
        participant_ids=[1, 2],
        categories=[],
    ),
)

# 운영 상태 변경은 전용 메서드를 사용합니다
client.projects.end_project(created.id, EndProjectRequest(end_year=2025))
client.projects.reactivate_project(created.id)
client.projects.delete_project(created.id)
```

`ProjectRequest`의 필드는 `project_id`, `project_name`, `club_id`, `status`, `category`, `page`, `size`, `sort_by`, `sort_direction`입니다. 기본값은 `status` `ACTIVE`, `page` 0, `size` 100, `sort_direction` `ASC`입니다. `category`는 해당 카테고리를 포함하는 프로젝트를 찾으며 `ProjectCategory`나 문자열을 받습니다. 알 수 없는 값은 응답의 `categories`에 문자열로 남습니다.

`ProjectWriteRequest`는 `name`, `description`, `start_year`가 필수입니다. `ENDED`로 생성하려면 `end_year`가 필요합니다. 수정할 때는 필드별 동작이 다릅니다.

| 필드 | 기본값일 때 | 비우는 방법 |
|---|---|---|
| `club_id` | 무소속으로 바뀝니다. 유지하려면 기존 값을 다시 보내야 합니다. | 기본값 그대로 두거나 `0` |
| `participant_ids`, `repositories`, `tech_stacks` | 빈 목록으로 덮어씁니다. 유지하려면 기존 값을 다시 보내야 합니다. | 기본값 그대로 둡니다. |
| `categories` | 기존 값을 유지합니다. | `[]` |
| `icon_key`, `deployment_url` | 기존 값을 유지합니다. | `""` |
| `status`, `end_year` | 수정에 반영되지 않습니다. | `end_project`, `reactivate_project` 사용 |

### NEIS API

**`client.neis`** - 나이스 교육정보시스템 데이터 조회

| 메서드                             | 설명         | 반환 타입             |
|---------------------------------|------------|-------------------|
| `get_meals(request=None)`       | 급식 데이터 조회  | `list[Meal]`      |
| `get_schedules(request=None)`   | 학사일정 조회    | `list[Schedule]`  |
| `get_timetables(request)`       | 시간표 데이터 조회 | `list[Timetable]` |

```python
from datetime import date

from datagsm_openapi import MealRequest, ScheduleRequest, TimetableRequest

# 급식 데이터 조회 (request를 생략하면 오늘 날짜)
meals = client.neis.get_meals(MealRequest(date=date.today()))

# 학사일정 조회
schedules = client.neis.get_schedules(
    ScheduleRequest(from_date=date(2026, 3, 1), to_date=date(2026, 3, 31))
)

# 시간표 조회
timetables = client.neis.get_timetables(
    TimetableRequest(grade=1, class_num=1, from_date=date(2026, 4, 6), to_date=date(2026, 4, 10))
)
```

- 세 요청 모두 `date` 또는 `from_date`, `to_date`로 날짜를 지정합니다. `date`와 기간은 함께 쓸 수 없고 기간은 최대 365일입니다.
- `TimetableRequest`는 `grade`, `class_num`이 필수이고 날짜 조건도 하나 이상 필요합니다.
- 학사일정의 `schedule_id` 형식이 바뀌어 이전에 저장한 ID는 조회되지 않습니다. 자세한 내용은 [변경 사항 및 마이그레이션](/migration)을 참고하세요.

### 응답 모델

응답 모델은 `datagsm_openapi.models`의 Pydantic 모델입니다. 필드는 [HTTP API 문서](/api/http)의 응답을 `snake_case`로 바꾼 이름입니다.

| 모델 | 주요 필드 |
|---|---|
| `StudentResponse` | `students`, `total_elements`, `total_pages` |
| `Student` | `id`, `name`, `sex`, `email`, `grade`, `class_num`, `number`, `student_number`, `major`, `specialty`, `role`, `dormitory_floor`, `dormitory_room`, `major_club`, `autonomous_club`, `github_id`, `github_url` |
| `ClubResponse` | `clubs`, `total_elements`, `total_pages` |
| `ClubDetail` | `id`, `name`, `type`, `status`, `founded_year`, `abolished_year`, `leader`, `participants` |
| `Club` | `id`, `name`, `type` |
| `ParticipantInfo` | `id`, `name`, `email`, `student_number`, `major`, `sex` |
| `ProjectResponse` | `projects`, `total_elements`, `total_pages` |
| `Project` | `id`, `name`, `description`, `club`, `participants`, `start_year`, `end_year`, `status`, `categories`, `icon_url`, `icon_key`, `deployment_url`, `repositories`, `tech_stacks` |
| `Meal` | `meal_id`, `school_code`, `school_name`, `office_code`, `office_name`, `meal_date`, `meal_type`, `meal_menu`, `meal_allergy_info`, `meal_calories`, `origin_info`, `nutrition_info`, `meal_serve_count` |
| `Schedule` | `schedule_id`, `school_code`, `school_name`, `office_code`, `office_name`, `schedule_date`, `academic_year`, `event_name`, `event_content`, `day_category`, `school_course_type`, `day_night_type`, `target_grades` |
| `Timetable` | `timetable_id`, `school_code`, `school_name`, `office_code`, `office_name`, `timetable_date`, `academic_year`, `semester`, `grade`, `class_num`, `period`, `subject` |

학번, 학과, 반 같은 값은 졸업생이나 학번이 없는 학생에서 `None`일 수 있습니다. `student.grade`, `student.student_number`, `student.major`, `club.leader`, `meal.meal_allergy_info`는 `None`을 확인하고 사용하세요.

## 예외 처리

SDK는 HTTP 상태 코드별로 구체적인 예외 타입을 제공합니다.

### 예외 종류

| 예외 타입                   | HTTP 상태 | 발생 상황               | 권장 처리 방법                        |
|-------------------------|---------|---------------------|---------------------------------|
| `UnauthorizedException` | 401     | API 키 유효하지 않음 또는 만료 | API 키 갱신 또는 재발급                 |
| `ForbiddenException`    | 403     | 필요한 권한 범위 부족        | 권한 범위 확인 및 요청                   |
| `BadRequestException`   | 400     | 잘못된 요청 파라미터         | 요청 파라미터 검증                      |
| `NotFoundException`     | 404     | 리소스를 찾을 수 없음        | ID 확인                           |
| `ConflictException`     | 409     | 이름, 이메일, 학번 등 중복    | 입력값 확인                          |
| `RateLimitException`    | 429     | Rate limit 초과       | 재시도 로직 구현 (Exponential Backoff) |
| `ServerErrorException`  | 5xx     | 서버 내부 오류            | 잠시 후 재시도 또는 관리자 문의              |
| `NetworkException`      | -       | 연결 실패 또는 타임아웃       | 네트워크 확인 후 재시도. `original_exception`에 원인이 있습니다 |
| `ValidationException`   | -       | 응답이 모델과 맞지 않음       | `validation_errors` 확인 후 SDK 업데이트 |
| `DataGsmException`      | 기타      | 기타 API 오류. 모든 예외의 부모 클래스 | 에러 메시지 확인 후 적절한 처리              |

모든 예외는 `message`, `status_code`, `response_body`를 가집니다. 예외는 `datagsm_openapi` 또는 `datagsm_openapi.exceptions`에서 가져옵니다.

### 예외 처리 예제

```python
import logging
from datagsm_openapi import DataGsmClient
from datagsm_openapi.exceptions import (
    UnauthorizedException,
    ForbiddenException,
    RateLimitException,
    BadRequestException,
    ConflictException,
    NotFoundException,
    ServerErrorException,
    DataGsmException
)

logger = logging.getLogger(__name__)

try:
    with DataGsmClient(api_key="your-api-key") as client:
        students = client.students.get_students(request)
        # 성공적인 응답 처리
except UnauthorizedException as e:
    # API 키 갱신 필요
    logger.error("API key expired or invalid", exc_info=e)
    renew_api_key()
except ForbiddenException as e:
    # 권한 범위 부족
    logger.warning("Insufficient permissions", exc_info=e)
    notify_user_about_permissions()
except RateLimitException as e:
    # Rate limit 초과 - 적절한 재시도 로직 구현 필요
    logger.warning("Rate limit exceeded", exc_info=e)
    # 실제로는 exponential backoff 등의 재시도 전략 구현 권장
except BadRequestException as e:
    # 잘못된 요청 파라미터
    logger.error(f"Invalid request parameters: {e.message}")
    validate_parameters()
except NotFoundException as e:
    # 리소스를 찾을 수 없음
    logger.warning(f"Resource not found: {e.message}")
except ConflictException as e:
    # 이름, 이메일, 학번 등 중복
    logger.warning(f"Resource conflict: {e.message}")
except ServerErrorException as e:
    # 서버 오류
    logger.error("Server error occurred", exc_info=e)
    notify_admin()
except DataGsmException as e:
    # 기타 예외
    logger.error(f"API error: {e.message}", exc_info=e)
```

from datagsm_openapi import DataGsmClient

## 문제 해결

### 자주 발생하는 문제

#### 401 Unauthorized 오류

**원인**: API 키가 유효하지 않거나 만료됨

**해결 방법**:

- API 키가 올바르게 설정되었는지 확인
- API 키가 만료되지 않았는지 확인
- 필요시 새로운 API 키 발급

#### 403 Forbidden 오류

**원인**: 요청한 API에 대한 권한 범위 부족

**해결 방법**:

- API 키의 권한 범위 확인 (`student:read`, `student:write` 등)
- 쓰기 권한 범위는 관리자 계정만 발급할 수 있습니다.
- 권한 범위 추가가 필요한 경우 관리자에게 문의

#### ValidationException 오류

**원인**: 서버 응답이 SDK 모델과 맞지 않음

**해결 방법**:

- SDK를 최신 버전으로 업데이트. 1.x는 `null`이 올 수 있는 필드를 필수로 선언해 이 오류가 날 수 있습니다.
- `validation_errors`에서 어떤 필드가 맞지 않는지 확인

## 마이그레이션

Python SDK에는 Deprecated API가 없고 2.0.0의 Breaking 변경만 있습니다. 서버 쪽 변경은 [변경 사항 및 마이그레이션](/migration)을 참고하십시오.

### 1.x → 2.0.0

아래는 1.2.0과 2.0.0을 비교한 내용입니다. 최소 Python 버전은 3.9로 같습니다.

- **Breaking**: `Student`의 `grade`, `class_num`, `number`, `student_number`, `major`가 필수 → 모두 `Optional`
  - 영향: 1.x는 서버가 `null`을 주면 `ValidationException`이 발생했습니다. 2.0에서는 `None`이 들어옵니다.
  - 대응: 값을 쓰기 전에 `None`을 확인합니다.
- **Breaking**: `ParticipantInfo`의 `student_number`, `major`, `ClubDetail.leader`가 필수 → 모두 `Optional`
  - 영향: 위와 같습니다. 부장이 없는 폐지 동아리도 읽을 수 있습니다.
  - 대응: `None`을 확인합니다.
- **Breaking**: `Meal.meal_allergy_info`는 `list[str]` → `Optional[list[str]]`
  - 영향: 서버가 `null`을 주면 `None`입니다.
  - 대응: 순회하기 전에 `None`을 확인합니다.
- **Breaking**: `TimetableRequest(start_date=..., end_date=...)` → `TimetableRequest(from_date=..., to_date=...)`
  - 영향: 이전 이름은 `TypeError`가 납니다. 1.x의 기간 조회는 서버에 없는 쿼리 이름으로 전송되었습니다.
  - 대응: 인자 이름을 바꿉니다.
- **Breaking**: `TimetableRequest`의 `grade`, `class_num` 기본값 0 → 필수 인자
  - 영향: 생략하면 `TypeError`가 납니다.
  - 대응: 값을 지정합니다.
- **Breaking**: `ClubSortBy.ABOLISHED_YEAR` → 제거
  - 영향: `AttributeError`가 납니다.
  - 대응: 다른 정렬 기준을 사용합니다.
- **동작 변경**: `ClubRequest.status`가 `status` 쿼리로 전송되어 서버에서 무시됨 → `clubStatus` 쿼리로 전송
  - 영향: 필터가 실제로 적용되어 결과가 달라질 수 있습니다.
  - 대응: 결과를 확인합니다. 인자 이름은 그대로입니다.
- **동작 변경**: `get_student`는 재학생 위주로 조회 → 졸업생, 자퇴생 포함
  - 영향: 이전에 `None`이던 ID가 값을 반환할 수 있습니다.
  - 대응: 호출부의 가정을 확인합니다.
- **동작 변경**: `get_project`는 `ACTIVE`만 조회 → `ACTIVE`, `ENDED`를 차례로 조회
  - 영향: 종료된 프로젝트도 반환되며 요청이 최대 2회 나갑니다.
  - 대응: 호출부의 가정을 확인합니다.
- **동작 변경**: 409가 `DataGsmException` → `ConflictException`
  - 영향: 부모 클래스가 같아 기존 처리는 그대로 동작합니다.
  - 대응: 필요하면 나눠서 처리합니다.
- **추가**: 쓰기 API, `ProjectCategory`, `ProjectRequest.category`, `StudentRequest.include_graduates`, `ClubRequest.founded_year`, `Project`의 `categories`, `icon_url`, `icon_key`, `deployment_url`, `repositories`, `tech_stacks`
  - 영향: 없습니다.
  - 대응: 필요하면 사용합니다.
