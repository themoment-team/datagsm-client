# OpenAPI

이 섹션에서는 학생, 동아리, 프로젝트 등의 데이터를 조회하고, 관리자 권한 범위로 학생, 동아리, 프로젝트 데이터를 변경할 수 있는 REST API 사용 방법을 다룹니다. OpenAPI를 통해 최신 데이터를 빠르게 조회할 수 있으며, 적절한 캐싱 전략을 활용하면 더욱 효율적으로 사용할 수 있습니다.
OpenAPI 사용 시 가장 중요한 요소는 필요한 데이터의 파악과 적절한 호출 빈도 설정입니다. 모든 HTTP 요청에는 요청량 제한(Rate Limit)이 적용되며, 과도한 요청은 시스템에 의해 거부될 수 있습니다. 또한 API 키 노출 방지를 위한 적절한 관리가 필요합니다.
이 섹션에서는 API의 기본 사용법, 실제 사용 예제, 그리고 더모먼트팀이 권장하는 API 키 관리 방법을 다룹니다.

### API 키 발급

API 키 발급 페이지에서 필요한 권한 범위를 설정하여 API 키를 발급받을 수 있습니다. 발급 시 최소 권한 원칙에 따라 서비스 운영에 필요한 최소한의 권한 범위만 선택하십시오. API 키는 계정당 1개만 발급할 수 있습니다. API 키 생성 시 설명을 추가하면 해당 키의 용도를 명확히 관리할 수 있습니다.

권한 범위는 `{데이터 종류}:{세부 권한}` 형식입니다. 콜론(**`:`**) 앞은 데이터 종류, 뒤는 허용되는 작업입니다. `student:*`처럼 `*`을 쓰면 해당 데이터의 조회와 쓰기가 모두 허용됩니다.

<br />
다음과 같은 권한 범위 설정이 존재하며, 필요한 항목을 선택하여 API 키를 발급받을 수 있습니다.

| 권한 범위 설정        | 설명                      | 발급 대상    |
|-----------------|-------------------------|----------|
| `student:read`  | 학생 데이터 조회               | 모든 계정    |
| `student:write` | 학생 데이터 생성, 수정           | 관리자 계정   |
| `student:*`     | 학생 데이터 모든 권한            | 관리자 계정   |
| `club:read`     | 동아리 데이터 조회              | 모든 계정    |
| `club:write`    | 동아리 데이터 생성, 수정, 삭제      | 관리자 계정   |
| `club:*`        | 동아리 데이터 모든 권한           | 관리자 계정   |
| `project:read`  | 프로젝트 데이터 조회             | 모든 계정    |
| `project:write` | 프로젝트 데이터 생성, 수정, 삭제     | 관리자 계정   |
| `project:*`     | 프로젝트 데이터 모든 권한          | 관리자 계정   |
| `neis:read`     | NEIS 데이터 조회             | 모든 계정    |
| `neis:*`        | NEIS 데이터 모든 권한          | 관리자 계정   |

일반 계정이 관리자 전용 권한 범위를 요청하면 발급이 거부됩니다. NEIS 데이터는 조회만 제공하므로 `neis:write`는 없습니다.

### API 키 유효기간과 갱신

| 항목        | 내용                                   |
|-----------|--------------------------------------|
| 유효기간      | 일반 계정 30일, 관리자 계정 365일               |
| 갱신 가능 기간  | 만료일로부터 15일이 지나기 전까지                  |
| 갱신 기한 경과  | 키가 삭제되므로 새로 발급해야 합니다                 |

웹 콘솔에서 키를 갱신하면 유효기간이 처음부터 다시 계산됩니다. 권한 범위나 설명을 바꾸지 않고 갱신하면 키 값이 그대로 유지됩니다. 갱신하면서 권한 범위나 설명을 바꾸면 키 값이 재발급되므로, 서비스에 저장한 키도 함께 교체해야 합니다. 권한 범위를 바꾸려고 키를 폐기할 필요는 없습니다.

키가 노출되었다면 웹 콘솔의 재발급을 사용하십시오. 키 값이 즉시 바뀌고 유효기간도 다시 계산되며, 이전 키는 더 이상 사용할 수 없습니다.

### 공통 사항

OpenAPI는 RESTful API로 설계되어 있으며, HTTP 메서드(`GET`, `POST` 등)를 사용하여 데이터를 조회하거나 수정할 수 있습니다. 모든 요청에는 발급받은 API 키를 헤더에 포함시켜야 합니다.

```http
X-API-KEY: your-api-key-here
```

API 키는 UUID 형식이며, 헤더가 없거나 형식이 잘못되었거나 만료되거나 유효하지 않은 키를 사용할 경우 `401 Unauthorized` 응답을 받게 됩니다.

API 키는 각각의 요청량 제한(Rate Limit)이 적용됩니다. 기본 한도는 60초에 100회이며, 이를 초과 시 `429 Too Many Requests` 응답이 반환됩니다. 필요한 경우 더 높은 요청량 제한을 위해 지원팀에 문의할 수 있습니다.

응답 본문이 있는 응답은 JSON 형식으로 반환되며, 오류 발생 시 적절한 HTTP 상태 코드와 함께 오류 메시지가 포함됩니다. 반환할 데이터가 없는 쓰기 요청은 본문 없이 `204 No Content`로 응답합니다.

### 반환 가능한 상태 코드

| 상태 코드                       | 설명                                 |
|-----------------------------|------------------------------------|
| `200 OK`                    | 요청이 성공적으로 처리됨                      |
| `204 No Content`            | 요청이 성공했고 반환할 본문이 없음 (삭제, 프로젝트 종료·재개) |
| `400 Bad Request`           | 잘못된 요청 파라미터 또는 본문                  |
| `401 Unauthorized`          | API 키가 없거나 유효하지 않거나 만료됨            |
| `403 Forbidden`             | 권한 범위 부족                           |
| `404 Not Found`             | 대상 데이터를 찾을 수 없음 (쓰기 API)           |
| `409 Conflict`              | 이름, 이메일, 학번 등이 이미 존재함 (쓰기 API)     |
| `429 Too Many Requests`     | 단위 시간에 너무 많은 요청량 발생                |
| `500 Internal Server Error` | 서버 내부 오류 발생                        |

### API 키 관리 권장 사항

더모먼트팀은 다음과 같은 API 키 관리 방법을 권장합니다.

- **최소 권한 원칙**: 서비스 운영에 필요한 최소한의 권한 범위만 부여합니다.
- **정기 갱신**: API 키를 정기적으로 갱신하여 보안을 강화합니다.
- **안전한 저장**: API 키를 안전하게 저장하고, 공개 저장소에 노출되지 않도록 주의합니다.
- **불필요한 키 폐기**: 더 이상 사용하지 않는 API 키는 즉시 폐기합니다.
