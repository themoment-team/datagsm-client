# DataGSM OAuth SDK Java / Kotlin

### 개요

**DataGSM OAuth SDK Java**는 DataGSM OAuth 인증을 Java 및 Kotlin 애플리케이션에서 쉽고 안전하게 구현할 수 있도록 설계된 공식 클라이언트 SDK입니다.

이 SDK를 사용하면 복잡한 OAuth 인증 플로우를 직접 구현할 필요 없이, 간단한 인터페이스를 통해 Authorization Code 교환, PKCE, 토큰 갱신, OpenID Connect, 사용자 데이터 조회 등의 기능을 손쉽게 사용할 수 있습니다.

### 주요 특징

| 특징                  | 설명                                                                  |
|---------------------|---------------------------------------------------------------------|
| **타입 안전성**          | 강타입 시스템으로 컴파일 타임에 오류를 검출하여 런타임 에러를 방지합니다.                           |
| **Kotlin 완벽 호환**    | Java와 Kotlin 프로젝트 모두에서 자연스럽게 사용할 수 있습니다.                            |
| **빌더 패턴**           | 직관적이고 유연한 클라이언트 구성을 지원합니다.                                          |
| **자동 리소스 관리**       | `AutoCloseable` 구현으로 리소스 누수를 자동으로 방지합니다.                            |
| **PKCE 지원**         | RFC 7636 표준 PKCE를 지원합니다. 공개 클라이언트와 기밀 클라이언트 모두에 권장합니다.             |
| **OpenID Connect**  | `id_token`, `nonce`, Discovery, JWKS 조회를 지원합니다.                       |
| **다양한 Grant 타입 지원** | Authorization Code, Refresh Token, Client Credentials Grant를 지원합니다. |
| **구체적인 예외 처리**      | HTTP 상태 코드별 전용 예외 타입을 제공하여 정확한 에러 핸들링이 가능합니다.                       |
| **검증된 HTTP 클라이언트**  | OkHttp 기반으로 안정적이고 효율적인 통신을 보장합니다.                                   |

## 빠른 시작

### 1. 클라이언트 초기화

`DataGsmOAuthClient` 인스턴스를 생성합니다. `client_secret`을 보관하는 백엔드는 `builder(clientId, clientSecret)`을, 시크릿을 보관할 수 없는 모바일·데스크톱 앱은 `builder(clientId)`를 사용합니다.

<CodeTabs>
  <CodeTab label="Java" language="java" code={`import team.themoment.datagsm.sdk.oauth.DataGsmOAuthClient;

// 기본 설정으로 클라이언트 생성
DataGsmOAuthClient client = DataGsmOAuthClient.builder("your-client-id", "your-client-secret").build();

// 커스텀 Base URL 설정 (선택사항)
DataGsmOAuthClient clientWithCustomUrl = DataGsmOAuthClient.builder("your-client-id", "your-client-secret")
    .authorizationBaseUrl("https://oauth.authorization.datagsm.kr")
    .userInfoBaseUrl("https://oauth.resource.datagsm.kr")
    .build();

// 공개 클라이언트 (client_secret 없음, PKCE 필수)
DataGsmOAuthClient publicClient = DataGsmOAuthClient.builder("your-client-id").build();`} />

  <CodeTab label="Kotlin" language="kotlin" code={`import team.themoment.datagsm.sdk.oauth.DataGsmOAuthClient

// 기본 설정으로 클라이언트 생성
val client = DataGsmOAuthClient.builder("your-client-id", "your-client-secret").build()

// 커스텀 Base URL 설정 (선택사항)

    .authorizationBaseUrl("https://oauth.authorization.datagsm.kr")
    .userInfoBaseUrl("https://oauth.resource.datagsm.kr")
    .build()

// 공개 클라이언트 (client_secret 없음, PKCE 필수)
val publicClient = DataGsmOAuthClient.builder("your-client-id").build()`} />

</CodeTabs>

`client_secret`을 `null`이나 빈 문자열로 넘기면 `IllegalArgumentException`이 발생합니다. 공개 클라이언트는 `builder(clientId)`로 만듭니다. 공개 클라이언트에서 `code_verifier` 없는 코드 교환이나 `getClientCredentialsToken`을 호출하면 `IllegalStateException`이 발생합니다.

### 2. OAuth 인증 플로우

DataGSM OAuth는 Authorization Code Grant 방식을 사용합니다.

#### Authorization URL 생성

사용자를 DataGSM OAuth 로그인 페이지로 리다이렉트하기 위한 URL을 생성합니다.

<CodeTabs>
  <CodeTab label="Java" language="java" code={`import java.util.List;
import team.themoment.datagsm.sdk.oauth.model.AuthorizationUrlBuilder;

String redirectUri = "https://myapp.com/callback";

AuthorizationUrlBuilder urlBuilder = client.createAuthorizationUrl(redirectUri)
    .state("random-csrf-token") // CSRF 방지 (권장)
    .scopes(List.of("datagsm:account_read", "datagsm:student_read")); // 필요한 권한 범위를 명시

String authorizationUrl = urlBuilder.build();
// 사용자를 authorizationUrl로 리다이렉트`} />

  <CodeTab label="Kotlin" language="kotlin" code={`import team.themoment.datagsm.sdk.oauth.model.AuthorizationUrlBuilder

val redirectUri = "https://myapp.com/callback"

val urlBuilder = client.createAuthorizationUrl(redirectUri)
    .state("random-csrf-token") // CSRF 방지 (권장)
    .scopes(listOf("datagsm:account_read", "datagsm:student_read")) // 필요한 권한 범위를 명시

val authorizationUrl = urlBuilder.build()
// 사용자를 authorizationUrl로 리다이렉트`} />

</CodeTabs>

권한 범위 표기는 `{appId}:{name}`이고 DataGSM 자사 앱의 Application ID는 `datagsm`입니다. 값은 클라이언트에 등록되어 있어야 하며, 등록되지 않은 값을 요청하면 `invalid_scope`가 됩니다. 필요한 값은 [권한 범위 레퍼런스](/oauth/scopes)를 참고하세요.

`scope`를 생략하면 서버는 클라이언트에 등록된 범위에서 `club_read`, `project_read`를 뺀 값을 부여합니다. 남는 값이 없으면 `invalid_scope`입니다.

사용자가 동의를 거부하면 `redirect_uri?error=access_denied&error_description=...&state=...`로 돌아옵니다. 콜백에서는 `state`를 저장한 값과 비교하고 `code`가 없는 경우를 먼저 처리하세요.

#### Authorization Code를 토큰으로 교환

<CodeTabs>
  <CodeTab label="Java" language="java" code={`import team.themoment.datagsm.sdk.oauth.model.TokenResponse;

// 콜백에서 받은 Authorization Code와 Redirect URI로 토큰 교환

// 토큰 사용

Long expiresIn = tokenResponse.getExpiresIn();     // 만료 시간(초)
List<String> scopes = tokenResponse.getScopes();   // 부여된 권한 범위 목록`} />

  <CodeTab label="Kotlin" language="kotlin" code={`import team.themoment.datagsm.sdk.oauth.model.TokenResponse

</CodeTabs>

#### 토큰 갱신

<CodeTabs>
  <CodeTab label="Java" language="java" code={`// Refresh Token으로 새로운 토큰 발급
TokenResponse newTokenResponse = client.refreshToken(refreshToken);

String newAccessToken = newTokenResponse.getAccessToken();
String newRefreshToken = newTokenResponse.getRefreshToken();

// Scope를 줄여서 갱신 (다운스코핑)

  <CodeTab label="Kotlin" language="kotlin" code={`// Refresh Token으로 새로운 토큰 발급

val newAccessToken = newTokenResponse.accessToken
val newRefreshToken = newTokenResponse.refreshToken

// Scope를 줄여서 갱신 (다운스코핑)

</CodeTabs>

갱신할 때마다 새 Refresh Token이 발급되므로 응답의 값으로 교체해 저장하세요. 이전 토큰을 다시 쓰면 `invalid_grant`가 되고 저장된 토큰도 삭제됩니다. 갱신 응답에는 `id_token`이 없습니다. `scope`로 좁혀도 저장된 범위는 유지됩니다.

## PKCE 지원

PKCE(Proof Key for Code Exchange, RFC 7636)는 Authorization Code 탈취 공격을 방지합니다. 공개 클라이언트는 반드시 사용하고, 기밀 클라이언트에도 권장합니다. PKCE로 발급된 code는 `code_verifier`로 교환하며 `client_secret`을 보내지 않습니다.

### PKCE 플로우

<CodeTabs>
  <CodeTab label="Java" language="java" code={`import team.themoment.datagsm.sdk.oauth.model.AuthorizationUrlBuilder;

String redirectUri = "myapp://callback";

// Step 1: PKCE가 활성화된 Authorization URL 생성
AuthorizationUrlBuilder urlBuilder = client.createAuthorizationUrl(redirectUri)
    .enablePkce()              // PKCE 자동 생성 (S256 메소드)
    .state("random-state");

String authorizationUrl = urlBuilder.build();
String codeVerifier = urlBuilder.getCodeVerifier(); // 반드시 저장!

// 사용자를 authorizationUrl로 리다이렉트

// Step 2: 콜백에서 Authorization Code를 받은 후 Code Verifier와 함께 토큰 교환
String authorizationCode = "received-code-from-callback";
TokenResponse tokenResponse = client.exchangeCodeForToken(
    authorizationCode,
    redirectUri,
    codeVerifier  // PKCE 검증용
);

System.out.println("Access Token: " + tokenResponse.getAccessToken());`} />

  <CodeTab label="Kotlin" language="kotlin" code={`import team.themoment.datagsm.sdk.oauth.model.AuthorizationUrlBuilder

val redirectUri = "myapp://callback"

// Step 1: PKCE가 활성화된 Authorization URL 생성

    .state("random-state")

val codeVerifier = urlBuilder.codeVerifier // 반드시 저장!

// 사용자를 authorizationUrl로 리다이렉트

// Step 2: 콜백에서 Authorization Code를 받은 후 Code Verifier와 함께 토큰 교환
val authorizationCode = "received-code-from-callback"
val tokenResponse = client.exchangeCodeForToken(
    authorizationCode,
    redirectUri,
    codeVerifier  // PKCE 검증용
)

println("Access Token: \${tokenResponse.accessToken}")`} />

</CodeTabs>

## Client Credentials Grant

사용자 인증 없이 클라이언트 자격증명만으로 토큰을 발급합니다. 서버-to-서버 통신에 사용합니다.

<CodeTabs>
  <CodeTab label="Java" language="java" code={`// 기본 scope로 토큰 발급
TokenResponse tokenResponse = client.getClientCredentialsToken();

// scope를 지정하여 토큰 발급
TokenResponse tokenResponseWithScope = client.getClientCredentialsToken(List.of("datagsm:account_read"));

System.out.println("Access Token: " + tokenResponse.getAccessToken());
System.out.println("Token Type: " + tokenResponse.getTokenType());
System.out.println("Expires In: " + tokenResponse.getExpiresIn());
// Client Credentials Grant에서는 Refresh Token이 발급되지 않습니다.`} />

  <CodeTab label="Kotlin" language="kotlin" code={`// 기본 scope로 토큰 발급
val tokenResponse = client.getClientCredentialsToken()

// scope를 지정하여 토큰 발급
val tokenResponseWithScope = client.getClientCredentialsToken(listOf("datagsm:account_read"))

println("Access Token: \${tokenResponse.accessToken}")
println("Token Type: \${tokenResponse.tokenType}")
println("Expires In: \${tokenResponse.expiresIn}")
// Client Credentials Grant에서는 Refresh Token이 발급되지 않습니다.`} />

</CodeTabs>

`scope`를 생략하면 클라이언트에 등록된 범위 전체가 부여되고, 등록되지 않은 값은 오류 없이 제외됩니다. 응답에 `refresh_token`과 `id_token`은 없습니다. 자세한 내용은 [Client Credentials 토큰 발급](/oauth/http/client-credentials)을 참고하세요.

## OpenID Connect

`openid`를 요청하면 토큰 응답에 `id_token`이 포함됩니다. SDK는 `id_token`의 서명을 검증하지 않습니다. `getJwkSet()`으로 받은 공개키와 JWT 라이브러리로 RS256 서명과 `iss`, `aud`, `exp`, `nonce`를 직접 검증하세요. 자세한 절차는 [OIDC 가이드](/oauth/oidc)를 참고하세요.

<CodeTabs>
  <CodeTab label="Java" language="java" code={`import java.util.List;
import java.util.UUID;
import team.themoment.datagsm.sdk.oauth.model.*;

String redirectUri = "https://myapp.com/callback";
String state = UUID.randomUUID().toString();
String nonce = UUID.randomUUID().toString(); // 세션에 저장해 두고 id_token 검증에 사용

// Step 1: openid를 포함해 인가 요청
AuthorizationUrlBuilder urlBuilder = client.createAuthorizationUrl(redirectUri)
    .state(state)
    .nonce(nonce)
    .scopes(List.of("openid", "datagsm:account_read"))
    .enablePkce();

String authorizationUrl = urlBuilder.build();
String codeVerifier = urlBuilder.getCodeVerifier();

// Step 2: 토큰 교환
TokenResponse tokenResponse = client.exchangeCodeForToken("received-code", redirectUri, codeVerifier);
String idToken = tokenResponse.getIdToken(); // openid를 요청했을 때만 값이 있습니다

### 로그아웃

`getLogoutEndpoint()`는 `POST /v1/oauth/logout` 주소를 반환합니다. Discovery에는 이 주소가 없으며 SDK가 인가 서버 주소에 고정 경로를 붙여 만든 값입니다. 이 엔드포인트는 브라우저의 SSO 세션 쿠키로 동작하므로 앱 서버에서 호출하면 세션이 삭제되지 않습니다. OIDC RP-Initiated Logout이 아니며, 이미 발급된 Access Token은 만료될 때까지 유효합니다.

SDK는 다음과 같은 API 메서드를 제공합니다.

### OAuth API

**`client.createAuthorizationUrl(redirectUri)`** - Authorization URL 생성

| 파라미터          | 타입       | 설명                    |

**`client.exchangeCodeForToken(code, redirectUri)`** - Authorization Code를 토큰으로 교환

| 파라미터          | 타입       | 설명                                    |
|---------------|----------|---------------------------------------|
| `code`        | `String` | Authorization Code                    |
| `redirectUri` | `String` | 원본 Authorization 요청에 사용한 Redirect URI |

| `codeVerifier` | `String` | Authorization URL 생성 시 생성한 Code Verifier |

| 반환 타입           | 설명        |
|-----------------|-----------|
| `TokenResponse` | 새로운 토큰 응답 |

| 파라미터           | 타입       | 설명            |

| `refreshToken` | `String` | Refresh Token |

| 반환 타입           | 설명        |
|-----------------|-----------|
| `TokenResponse` | 새로운 토큰 응답 |

| 파라미터           | 타입                         | 설명                                                 |

## 예외 처리

SDK는 HTTP 상태 코드별로 구체적인 예외 타입을 제공합니다.

### 예외 종류

| 예외 타입                   | HTTP 상태 | 발생 상황                                  | 권장 처리 방법                        |
|-------------------------|---------|----------------------------------------|---------------------------------|
| `BadRequestException`   | 400     | 잘못된 파라미터, `invalid_grant`, `invalid_scope` | `getErrorCode()` 확인 후 재인증 또는 요청 수정 |
| `UnauthorizedException` | 401     | Access Token 무효 또는 만료, `invalid_client` | 토큰 갱신 또는 클라이언트 자격증명 확인           |
| `ForbiddenException`    | 403     | 필요한 권한 범위 부족                           | 권한 범위 확인 및 요청                   |
| `NotFoundException`     | 404     | 요청한 리소스를 찾을 수 없음                       | 요청 경로 확인                        |
| `RateLimitException`    | 429     | 요청 한도 초과                               | 재시도 로직 구현 (Exponential Backoff) |
| `ServerErrorException`  | 500, 502, 503, 504 | 서버 오류                       | 잠시 후 재시도 또는 관리자 문의              |
| `DataGsmException`      | 기타      | 네트워크 오류 등 기타 오류. 모든 예외의 부모 클래스         | 에러 메시지 확인 후 적절한 처리              |

토큰 요청과 `/userinfo` 호출의 한도는 OAuth 클라이언트 기준 분당 300회입니다.

### 서버 오류 정보

모든 예외는 `DataGsmException`을 상속하며 서버 응답을 파싱한 값을 제공합니다.

| 메서드                     | 설명                                                                          |
|-------------------------|-----------------------------------------------------------------------------|
| `getStatusCode()`       | HTTP 상태 코드. 응답이 없으면 `DataGsmException.NO_STATUS_CODE`(-1)                    |
| `hasStatusCode()`       | HTTP 상태 코드가 있는지 여부                                                          |
| `getErrorCode()`        | 토큰 요청은 `invalid_grant` 같은 `error` 값, `/userinfo`는 `UNAUTHORIZED` 같은 `status` 값 |
| `getErrorDescription()` | `error_description` 또는 `message` 값                                           |
| `getResponseBody()`     | 원본 응답 본문                                                                    |

### 토큰 보안 가이드라인

- **Access Token**: 짧은 유효기간을 가지며, 메모리에서만 관리하세요.
- **Refresh Token**: 안전한 저장소(암호화된 DB, Secure Storage 등)에 보관하세요.
- **PKCE 사용**: 공개 클라이언트는 반드시 PKCE를 활성화하고, 기밀 클라이언트에도 권장합니다.
- **Client Secret**: 시크릿은 백엔드에만 두고 프런트 코드에 넣지 마세요.
- **HTTPS 사용**: 모든 통신은 반드시 HTTPS를 통해 이루어져야 합니다.
- **State 파라미터**: Authorization URL 생성 시 CSRF 방지를 위해 `state` 파라미터를 설정하세요.

## 문제 해결

### 자주 발생하는 문제

#### 401 Unauthorized 오류

**원인**: Access Token이 유효하지 않거나 만료됨

**해결 방법**:

- Access Token의 유효기간 확인 (`tokenResponse.getExpiresIn()`)
- `refreshToken()` 메서드로 새 토큰 발급
- Refresh Token도 만료된 경우 재인증 필요

#### 403 Forbidden 오류

**원인**: 요청한 리소스에 대한 권한 범위 부족

**해결 방법**:

- `getUserInfo`에는 `account_read` 또는 `self_read`가 필요합니다. `student_read`만 있으면 403입니다.
- 필요한 권한 범위를 클라이언트에 등록하고 인가 요청의 `scope`에 명시
- 권한 범위를 넓히면 사용자에게 동의 화면이 다시 표시되고, 기존 Refresh Token은 이전 범위를 유지하므로 재로그인이 필요합니다.

#### 400 Bad Request 오류

**원인**: 잘못된 요청 파라미터

**해결 방법**:

- Authorization Code가 유효한지 확인
- Code가 이미 사용되었는지 확인 (일회용)
- Client ID, Client Secret이 올바른지 확인
- `redirectUri`가 Authorization 요청 시와 동일한지 확인
- PKCE 사용 시 `codeVerifier`가 올바른지 확인
- `invalid_scope`면 요청한 값이 클라이언트에 등록되어 있는지 확인

#### 429 Too Many Requests 오류

**원인**: OAuth 클라이언트 기준 분당 요청 한도 초과

**해결 방법**:

- 사용자 데이터를 캐시하고 요청 횟수를 줄이기
- Exponential Backoff로 재시도
