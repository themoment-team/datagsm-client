# OAuth HTTP API

### 개요

OAuth HTTP API를 사용하면 HTTP 요청을 통해 직접 OAuth 인증 플로우를 구현할 수 있습니다.
SDK를 사용하지 않고 REST API를 직접 호출하여 더 세밀한 제어가 필요한 경우에 적합합니다.

이 기술 문서는 DataGSM OAuth의 모든 HTTP 엔드포인트에 대한 상세한 내용을 다룹니다.

### 기본 설정

#### Base URL

**Authorization Server:**
```
https://oauth.authorization.datagsm.kr
```

**UserInfo Server:**
```
https://oauth.resource.datagsm.kr
```

개발 환경에서는 다음 URL을 사용할 수 있습니다.

```
http://localhost:8081
```

#### Content-Type

`POST /v1/oauth/token`은 두 가지 요청 형식을 받습니다. 응답은 JSON입니다.

```http
Content-Type: application/x-www-form-urlencoded
Content-Type: application/json
```

표준 OAuth 라이브러리는 form 형식을 사용합니다. JSON 본문에서는 호환용으로 `camelCase` 별칭과 `scope` 배열도 허용되지만, 신규 연동은 `snake_case`와 공백 구분 문자열을 사용하십시오. form 요청에는 별칭이 적용되지 않습니다.

#### 클라이언트 인증

| 방식 | Discovery 값 | 사용 방법 |
|---|---|---|
| 본문 전달 | `client_secret_post` | 본문에 `client_secret` 포함 |
| HTTP Basic | `client_secret_basic` | `Authorization: Basic` 헤더 사용 |
| 시크릿 없음 | `none` | PKCE 코드 교환과 토큰 갱신에서 `client_secret` 생략 |

Basic 헤더와 본문 `client_secret`을 함께 보내거나, 본문 `client_id`가 헤더와 다르거나, 같은 파라미터를 두 번 보내면 `invalid_request`로 거부됩니다. 디코딩할 수 없는 Basic 헤더는 `401 invalid_client`입니다.

#### 프로토콜

프로덕션 환경에서는 **반드시 HTTPS**를 사용해야 합니다. HTTP는 토큰 탈취의 위험이 있으므로
개발 환경(localhost)에서만 사용하십시오.

### 공통 응답 구조

#### 토큰 응답 구조

토큰을 발급하거나 갱신하는 엔드포인트는 다음과 같은 공통 응답 구조를 사용합니다.

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...",
  "scope": "openid datagsm:account_read datagsm:student_read",
  "id_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9..."
}
```

| 필드            | 타입     | 설명                                             |
|-----------------|----------|--------------------------------------------------|
| `access_token`  | `String` | JWT 형식의 Access Token (1시간 유효)             |
| `token_type`    | `String` | 토큰 타입 (`Bearer` 고정)                        |
| `expires_in`    | `Int`    | Access Token의 만료 시간 (초 단위, 3600 = 1시간) |
| `refresh_token` | `String?` | Refresh Token (30일 유효). Client Credentials에서는 `null` |
| `scope`         | `String` | 발급된 권한 범위 (공백으로 구분)                 |
| `id_token`      | `String?` | `openid`로 인가된 코드를 교환할 때만 값이 있습니다. 그 외에는 `null` |

토큰 응답에는 `Cache-Control: no-store`, `Pragma: no-cache` 헤더가 포함됩니다.

### 사용 가능한 엔드포인트

| 엔드포인트            | 메서드 | 설명                                                         | 기술 문서                                    |
|-----------------------|--------|--------------------------------------------------------------|----------------------------------------------|
| `/v1/oauth/authorize` | `GET`  | OAuth 인증 흐름 시작 (사용자를 로그인 페이지로 리다이렉트)   | [상세 기술 문서](/oauth/http/authorize)      |
| `/v1/oauth/token`     | `POST` | Authorization Code를 Access Token으로 교환 (통합 엔드포인트) | [상세 기술 문서](/oauth/http/token-exchange) |
| `/v1/oauth/token`     | `POST` | Refresh Token으로 새 Access Token 발급 (통합 엔드포인트)     | [상세 기술 문서](/oauth/http/token-refresh)  |
| `/v1/oauth/token`     | `POST` | 클라이언트 자격으로 Access Token 발급 (통합 엔드포인트)      | [상세 기술 문서](/oauth/http/client-credentials) |
| `/userinfo`           | `GET`  | Access Token으로 사용자 데이터 조회                          | [상세 기술 문서](/oauth/http/userinfo)       |
| `/v1/oauth/jwks`      | `GET`  | 토큰 서명 검증용 공개 키 조회                                | [OIDC 가이드](/oauth/oidc)                   |
| `/.well-known/openid-configuration` | `GET` | OIDC Discovery 문서 조회                       | [OIDC 가이드](/oauth/oidc)                   |
| `/v1/oauth/logout`    | `POST` | SSO 세션 종료                                                | [OIDC 가이드](/oauth/oidc)                   |

### 에러 처리

오류 응답 형식은 오류 종류에 따라 다릅니다.

#### OAuth 오류 형식

토큰 발급과 인가 요청의 OAuth 오류는 다음 형식입니다.

```json
{
  "error": "invalid_request",
  "error_description": "code 파라미터가 필요합니다."
}
```

| `error` | 상태 코드 | 설명 |
|---|---|---|
| `invalid_request` | `400` | 필수 파라미터 누락, 중복 파라미터, 잘못된 요청 형식 |
| `invalid_client` | `401` | 없는 클라이언트 또는 클라이언트 인증 실패 |
| `invalid_grant` | `400` | 코드나 Refresh Token이 유효하지 않음 |
| `invalid_scope` | `400` | 허용 범위를 벗어난 scope |
| `unsupported_grant_type` | `400` | 지원하지 않는 `grant_type` |

`Accept` 헤더에 `text/html`이 있으면 `/v1/oauth/token`을 제외한 OAuth 오류는 HTML 오류 페이지로 응답합니다.

#### 공통 응답 형식

`/userinfo` 인증 실패, 요청 한도 초과처럼 OAuth 오류가 아닌 경우는 다음 형식입니다.

```json
{
  "status": "401 UNAUTHORIZED",
  "code": 401,
  "message": "만료된 토큰입니다."
}
```

#### HTTP 상태 코드

| 상태 코드                       | 설명                                     | 해결 방법                                   |
|-----------------------------|----------------------------------------|-----------------------------------------|
| `400 Bad Request`           | 잘못된 요청 파라미터 또는 필수 파라미터 누락              | 요청 파라미터를 확인하고 필수 필드가 모두 포함되었는지 확인하세요.   |
| `401 Unauthorized`          | 인증 실패 (잘못된 Client ID·Secret, 만료된 토큰 등) | Client ID·Secret이 올바른지, 토큰이 유효한지 확인하세요. |
| `403 Forbidden`             | 권한 범위 부족                              | 토큰의 scope를 확인하세요. [권한 범위](/oauth/scopes)를 참고하세요. |
| `429 Too Many Requests`     | 요청 한도 초과                              | 잠시 후 다시 시도하세요.                          |
| `500 Internal Server Error` | 서버 내부 오류                               | 잠시 후 다시 시도하거나 지원팀에 문의하세요.               |

### 기본 요청 예시

다음은 cURL을 사용한 기본적인 OAuth 플로우 예시입니다.

#### 요청 한도

OAuth 클라이언트 기준 분당 300회, 로그인 계정 기준 10분 10회입니다. 초과하면 `429 Too Many Requests`로 응답합니다. `/userinfo`는 `X-RateLimit-Limit`, `X-RateLimit-Remaining` 헤더를 함께 보내고, 한도를 넘으면 `Retry-After` 헤더도 보냅니다.

#### 1. 인증 흐름 시작

브라우저에서 다음 URL로 리다이렉트합니다. 사용자가 로그인하고 동의하면 `redirect_uri`로 Authorization Code가 전달됩니다. 사용자가 동의를 거부하면 `code` 대신 `error=access_denied`가 전달됩니다.

```
https://oauth.authorization.datagsm.kr/v1/oauth/authorize?client_id=your-client-id&redirect_uri=https%3A%2F%2Fyour-app.com%2Fcallback&response_type=code&state=random-state-value&scope=datagsm%3Aaccount_read%20datagsm%3Astudent_read
```

#### 2. 토큰 교환

```bash
curl -X POST "https://oauth.authorization.datagsm.kr/v1/oauth/token" \
  -u "your-client-id:your-client-secret" \
  -d "grant_type=authorization_code" \
  -d "code=abc123def456" \
  --data-urlencode "redirect_uri=https://your-app.com/callback"
```

#### 3. 사용자 데이터 조회

```bash
curl -X GET "https://oauth.resource.datagsm.kr/userinfo" \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9..."
```

### 보안 고려사항

#### Client Secret 보호

- **Client Secret은 절대 클라이언트 측(브라우저, 모바일 앱)에 노출하지 마세요.**
- 토큰 교환은 반드시 서버에서 수행해야 합니다.
- 환경 변수나 보안 볼트에 안전하게 저장하세요.

#### HTTPS 사용

- 프로덕션 환경에서는 모든 OAuth 통신에 HTTPS를 사용하세요.
- HTTP는 토큰과 비밀번호가 평문으로 전송되어 위험합니다.

#### 토큰 만료 처리

- Access Token은 1시간 후 만료됩니다.
- 만료 시 Refresh Token을 사용하여 새 Access Token을 발급받으세요.
- Refresh Token도 30일 후 만료되므로, 만료 전에 재로그인이 필요합니다.
