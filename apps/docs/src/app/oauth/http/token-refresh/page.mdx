# 토큰 갱신

### 엔드포인트

```http
POST /v1/oauth/token
```

**주의**: 이 엔드포인트는 토큰 교환(`/v1/oauth/token`)과 동일한 통합 엔드포인트입니다.
`grant_type` 파라미터로 구분됩니다.

### 설명

Refresh Token을 사용하여 새로운 Access Token과 Refresh Token을 발급받습니다.
Access Token이 만료되었을 때(1시간 후) 사용자가 다시 로그인하지 않고도 새로운 Access Token을 받을 수 있습니다.

Refresh Token은 **30일의 유효기간**을 가지며, 갱신 시 새로운 Refresh Token도 함께 발급됩니다. 이 요청은 앱의 백엔드에서 보냅니다. 갱신 응답에는 `id_token`이 없습니다.

### 요청 파라미터

요청 본문은 `application/x-www-form-urlencoded` 또는 `application/json` 형식으로 보냅니다.

| 파라미터 | 타입 | 필수 여부 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| `grant_type` | `String` | 필수 | 요청 타입 (`refresh_token` 고정) | `refresh_token` |
| `refresh_token` | `String` | 필수 | 이전에 발급받은 Refresh Token | `eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...` |
| `client_id` | `String` | 필수 | DataGSM에서 발급받은 클라이언트 ID | `your-client-id` |
| `client_secret` | `String` | 선택 | 클라이언트 시크릿. 보내면 서버가 검증합니다. Basic 헤더로 보낼 수도 있습니다 | `your-client-secret` |
| `scope` | `String` | 선택 | 저장된 범위 안에서 이번 Access Token의 범위를 좁힐 때 사용 (공백으로 구분) | `datagsm:account_read` |

`scope`로 좁혀도 저장된 범위는 유지되므로 다음 갱신에서 원래 범위를 다시 받을 수 있습니다. 저장된 범위를 넘으면 `invalid_scope`입니다. 기존 Refresh Token은 발급 당시의 범위를 유지합니다. 범위를 넓히려면 사용자가 다시 로그인해야 합니다.

### 응답

#### 성공 응답 (200 OK)

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...",
  "scope": "datagsm:account_read datagsm:student_read"
}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `access_token` | `String` | 새로 발급된 JWT 형식의 Access Token (1시간 유효) |
| `token_type` | `String` | 토큰 타입 (`Bearer` 고정) |
| `expires_in` | `Int` | Access Token의 만료 시간 (초 단위, 3600 = 1시간) |
| `refresh_token` | `String` | 새로 발급된 Refresh Token (30일 유효) |
| `scope` | `String` | 발급된 권한 범위 (공백으로 구분) |

응답에는 `Cache-Control: no-store`, `Pragma: no-cache` 헤더가 포함됩니다. `id_token` 필드는 항상 `null`입니다.

### 오류 응답

| 상태 코드 | 오류 | 원인 |
| --- | --- | --- |
| `400 Bad Request` | `invalid_request` | `refresh_token`, `client_id` 누락, 클라이언트 인증 방식 중복, 파라미터 중복 |
| `400 Bad Request` | `invalid_grant` | Refresh Token이 유효하지 않거나 만료됨, 이미 사용한 토큰, 다른 클라이언트의 토큰 |
| `400 Bad Request` | `invalid_scope` | 요청한 `scope`가 저장된 범위를 넘음 |
| `401 Unauthorized` | `invalid_client` | 없는 클라이언트, `client_secret` 불일치 |
| `404 Not Found` | - | 토큰의 사용자 계정을 찾을 수 없음 |
| `429 Too Many Requests` | - | 클라이언트 요청 한도 초과 |

  <CodeTab label="Java" language="java" code={`import java.net.http.*;
import java.net.URI;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.JsonNode;
import java.util.Map;

public class OAuthRefreshService {
    private static final HttpClient client = HttpClient.newHttpClient();
    private static final ObjectMapper mapper = new ObjectMapper();

    public static TokenResponse refreshAccessToken(String refreshToken, String clientId) throws Exception {
        // 요청 본문 생성
        Map<String, String> requestBody = Map.of(
            "grant_type", "refresh_token",
            "refresh_token", refreshToken,
            "client_id", clientId
        );
        String requestBodyJson = mapper.writeValueAsString(requestBody);

        // HTTP 요청 생성
        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://oauth.authorization.datagsm.kr/v1/oauth/token"))
            .header("Content-Type", "application/json")
            .POST(HttpRequest.BodyPublishers.ofString(requestBodyJson))
            .build();

        // 요청 전송
        HttpResponse<String> response = client.send(
            request,
            HttpResponse.BodyHandlers.ofString()
        );

        // 응답 처리
        if (response.statusCode() != 200) {
            throw new RuntimeException("Failed to refresh token: " + response.body());
        }

        JsonNode jsonNode = mapper.readTree(response.body());
        return new TokenResponse(
            jsonNode.get("access_token").asText(),
            jsonNode.get("refresh_token").asText(),
            jsonNode.get("expires_in").asInt()
        );
    }

    public static class TokenResponse {
        public final String accessToken;
        public final String refreshToken;
        public final int expiresIn;

        public TokenResponse(String accessToken, String refreshToken, int expiresIn) {
            this.accessToken = accessToken;
            this.refreshToken = refreshToken;
            this.expiresIn = expiresIn;
        }
    }

    public static void main(String[] args) throws Exception {
        String oldRefreshToken = "eyJhbGciOiJSUzI1NiIsImtpZCI6Ii4uLiJ9...";
        TokenResponse tokens = refreshAccessToken(oldRefreshToken, "your-client-id");

        System.out.println("Expires In: " + tokens.expiresIn + " seconds");
    }
}`} />

import java.net.http.HttpRequest
import java.net.http.HttpResponse

import com.fasterxml.jackson.annotation.JsonIgnoreProperties

import com.fasterxml.jackson.module.kotlin.jacksonObjectMapper
import com.fasterxml.jackson.module.kotlin.readValue

data class RefreshRequest(
    val grant_type: String = "refresh_token",
    val refresh_token: String,
    val client_id: String
)

@JsonIgnoreProperties(ignoreUnknown = true)
data class TokenResponse(
    @JsonProperty("access_token")
    val accessToken: String,
    @JsonProperty("refresh_token")
    val refreshToken: String,
    @JsonProperty("expires_in")
    val expiresIn: Int
)

class OAuthRefreshService {

    private val mapper = jacksonObjectMapper()

    fun refreshAccessToken(refreshToken: String, clientId: String): TokenResponse {

            refresh_token = refreshToken,
            client_id = clientId

### 자동 토큰 갱신 구현

Access Token이 만료되기 전에 백엔드에서 갱신하는 로직을 구현하는 것이 좋습니다. 브라우저에서는 `/v1/oauth/token`을 직접 호출할 수 없으므로 토큰 관리는 백엔드가 맡습니다.

#### JavaScript 예제 (Node.js 백엔드)

```javascript
const REFRESH_MARGIN_MS = 5 * 60 * 1000; // 만료 5분 전

async function getValidAccessToken(session) {
  if (Date.now() < session.expiresAt - REFRESH_MARGIN_MS) {
    return session.accessToken;
  }

  try {
    const tokens = await refreshAccessToken(session.refreshToken, 'your-client-id');
    session.accessToken = tokens.accessToken;
    session.refreshToken = tokens.refreshToken;
    session.expiresAt = Date.now() + tokens.expiresIn * 1000;
    return session.accessToken;
  } catch (error) {
    // 갱신 실패 시 세션을 지우고 재로그인을 유도합니다.
    session.destroy();
    throw error;
  }
}
```

같은 세션의 갱신 요청은 하나씩 처리하세요. 이전 Refresh Token으로 동시에 요청하면 뒤의 요청이 재사용으로 판단됩니다.

### 보안 주의사항

#### Refresh Token 보호

- Refresh Token은 30일 동안 유효하므로 안전하게 저장해야 합니다.
- **권장**: HttpOnly 쿠키 또는 서버 세션에 저장
- **주의**: localStorage는 XSS 공격에 취약

#### 토큰 로테이션

- 토큰 갱신 시 새로운 Refresh Token도 함께 발급됩니다.
- 이전 Refresh Token은 무효화되므로, 항상 새로 발급된 Refresh Token을 사용하세요.
- 이전 Refresh Token을 다시 사용하면 저장된 Refresh Token도 삭제되어 `invalid_grant`로 거부됩니다. 이 경우 사용자가 다시 로그인해야 합니다.
- 계정과 클라이언트 조합마다 유효한 Refresh Token은 하나입니다. 같은 사용자가 다른 기기에서 다시 로그인하면 이전 Refresh Token은 더 이상 쓸 수 없습니다.

#### 만료 처리

- Refresh Token이 만료되면 (`400 invalid_grant`) 사용자는 다시 로그인해야 합니다.
- 갱신 실패를 감지하면 앱 세션을 정리하고 로그인 화면으로 안내하세요.
