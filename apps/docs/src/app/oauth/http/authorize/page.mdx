# 인증 흐름 시작

### 엔드포인트

```http
GET /v1/oauth/authorize
```

### 설명

OAuth 인증 흐름의 진입점입니다. 클라이언트가 사용자를 이 엔드포인트로 리다이렉트하면, DataGSM OAuth 서버가 요청을 검증한 뒤 SSO 세션과 동의 기록에 따라 로그인 화면, 동의 화면, 코드 발급 중 하나로 진행합니다. 인가가 끝나면 `redirect_uri`로 Authorization Code가 전달되고, 사용자가 동의를 거부하면 `error=access_denied`가 전달됩니다.

### 요청 파라미터

모든 파라미터는 쿼리 스트링(Query String)으로 전달합니다.

| 파라미터                    | 타입       | 필수 여부     | 설명                                                | 예시                                            |
|-------------------------|----------|-----------|---------------------------------------------------|-----------------------------------------------|
| `client_id`             | `String` | 필수        | DataGSM에서 발급받은 클라이언트 ID                           | `your-client-id`                              |
| `redirect_uri`          | `String` | 필수        | 인증 완료 후 code를 전달받을 URI. 등록값과 정확히 일치해야 함     | `https://your-app.com/callback`               |
| `response_type`         | `String` | 선택        | 응답 타입 (`code` 고정, 기본값 `code`)                     | `code`                                        |
| `state`                 | `String` | 선택 (권장)   | CSRF 공격 방지용 임의 문자열. 콜백 시 그대로 반환됨                  | `randomString123`                             |
| `code_challenge`        | `String` | 선택 (PKCE) | PKCE Code Verifier를 SHA-256 해싱 후 Base64URL 인코딩한 값 | `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM` |
| `code_challenge_method` | `String` | 조건부 필수 | `code_challenge`를 보내면 필수. `S256`을 사용합니다. 생략하거나 지원하지 않는 값이면 `invalid_request` | `S256`                                        |
| `scope`                 | `String` | 선택 (명시 권장) | 요청할 권한 범위 목록 (공백으로 구분)                        | `datagsm:account_read datagsm:student_read`   |
| `nonce`                 | `String` | 선택 (OIDC 권장) | `id_token`에 그대로 담기는 재전송 방지 값                   | `n-0S6_WzA2Mj`                                |

### Scope 사용 방식

필요한 권한 범위를 **명시**하십시오. 권한 범위는 `{applicationId}:{scopeName}` 형식이며, DataGSM 기본 권한 범위의 Application ID는 `datagsm`입니다. `openid`만 접두어가 없습니다. 각 범위의 의미는 [권한 범위](/oauth/scopes)를 참고하세요.

| 요청 | 서버가 결정하는 범위 |
|---|---|
| 명시 | 요청한 값 그대로. `openid`는 등록 검사에서 제외됩니다 |
| 생략 또는 빈 값 | 클라이언트 권한 범위 전체에서 `club_read`, `project_read`를 뺀 값. 남는 값이 없으면 `invalid_scope` |
| `openid`만 요청 | `account_read`, `student_read` 중 클라이언트가 가진 값. 둘 다 없으면 `self_read`, 그것도 없으면 `invalid_scope` |

요청한 값 중 클라이언트에 등록되지 않은 값이 있으면 `invalid_scope`로 거부됩니다. 정확한 문자열은 클라이언트 등록 화면에서 확인할 수 있습니다.

여러 권한 범위를 요청하는 경우 공백으로 구분하며, URL에서는 공백을 `%20`으로 인코딩합니다.

### 응답

#### 성공 응답 (302 Found)

요청 상태에 따라 다음 중 하나로 리다이렉트됩니다. 로그인 화면이나 동의 화면에서 처리할 수 있는 시간은 **10분**입니다.

| 상태 | 동작 |
|---|---|
| SSO 세션이 있고 요청 범위 전체에 동의 기록이 있음 | 화면 없이 바로 `redirect_uri`로 코드 발급 |
| SSO 세션은 있으나 동의 기록이 없거나 새 범위가 포함됨 | 동의 화면 표시 |
| SSO 세션이 없음 | 로그인 화면 표시. 비밀번호 로그인에 성공하면 요청 범위에 대한 동의가 함께 기록됩니다 |
| 관리자의 정보 수정 요청이 남은 학생 | SSO 세션이 있어도 로그인 화면 표시. 요청된 정보를 입력해야 코드가 발급됩니다 |

SSO 세션은 쿠키 기반이며 8시간 유지됩니다. `@gsm.hs.kr` 이메일만 로그인할 수 있습니다. `ACTIVE`가 아닌 계정(승인 대기 선생님 등)은 로그인이 `403`으로 거부됩니다.

인가가 끝나면 아래 형태로 `redirect_uri`에 Authorization Code가 전달됩니다.

```
https://your-app.com/callback?code={authorization_code}&state={state}
```

| 파라미터    | 설명                                  |
|---------|-------------------------------------|
| `code`  | Authorization Code (5분 유효, 일회성)     |
| `state` | 요청 시 전달한 `state` 값 (생략한 경우 포함되지 않음) |

#### 동의 거부

사용자가 동의를 거부하면 `code` 없이 다음 형태로 돌아옵니다. 콜백은 `code`가 없는 경우를 반드시 처리해야 합니다.

```
https://your-app.com/callback?error=access_denied&error_description=...&state={state}
```

### 오류 응답

아래 오류는 `redirect_uri`로 돌아가지 않습니다. 브라우저에서는 DataGSM 오류 페이지로 표시되므로, 연동 중에는 요청 파라미터를 먼저 확인하세요.

| 상태 코드 | 오류 | 원인 |
|---|---|---|
| `400 Bad Request` | - | `client_id` 또는 `redirect_uri` 누락 |
| `400 Bad Request` | `invalid_request` | `response_type`이 `code`가 아님, 등록되지 않은 `redirect_uri`, `code_challenge`와 함께 보낸 `code_challenge_method`가 없거나 지원하지 않는 값 |
| `400 Bad Request` | `invalid_scope` | 클라이언트에 등록되지 않은 scope 요청, 또는 기본으로 부여할 scope가 없음 |
| `401 Unauthorized` | `invalid_client` | 존재하지 않는 `client_id` |
| `429 Too Many Requests` | - | 클라이언트 요청 한도 초과 |

### 요청 예시

#### URL 구성 (PKCE)

```javascript
// 1. PKCE code_verifier 생성
function generateCodeVerifier() {
  const array = new Uint8Array(32);
  crypto.getRandomValues(array);
  const base64 = btoa(String.fromCharCode(...array));
  return base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

// 2. code_challenge 생성 (SHA-256)
async function generateCodeChallenge(verifier) {
  const data = new TextEncoder().encode(verifier);
  const hash = await crypto.subtle.digest('SHA-256', data);
  const base64 = btoa(String.fromCharCode(...new Uint8Array(hash)));
  return base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

// 3. state 생성 및 저장
const state = crypto.randomUUID();
const codeVerifier = generateCodeVerifier();
const codeChallenge = await generateCodeChallenge(codeVerifier);

sessionStorage.setItem('oauth_state', state);
sessionStorage.setItem('oauth_code_verifier', codeVerifier);

// 4. 인증 URL 구성 후 리다이렉트
const params = new URLSearchParams({
  client_id: 'your-client-id',
  redirect_uri: 'https://your-app.com/callback',
  response_type: 'code',
  state,
  scope: 'datagsm:account_read datagsm:student_read',
  code_challenge: codeChallenge,
  code_challenge_method: 'S256',
});

window.location.href = `https://oauth.authorization.datagsm.kr/v1/oauth/authorize?${params}`;
```

#### URL 구성 (서드파티 권한 범위)

외부 애플리케이션이 자체 권한 범위를 정의한 경우에는 해당 애플리케이션의 Application ID를 포함해 `{applicationId}:{scopeName}` 형식으로 전달합니다.

```javascript
const params = new URLSearchParams({
  client_id: 'your-client-id',
  redirect_uri: 'https://your-app.com/callback',
  response_type: 'code',
  scope: 'your-application-id:profile',
});

window.location.href = `https://oauth.authorization.datagsm.kr/v1/oauth/authorize?${params}`;
```

#### 콜백 처리 예시

```javascript
// redirect_uri 페이지에서 결과 수신
const params = new URLSearchParams(window.location.search);
const code = params.get('code');
const error = params.get('error');
const returnedState = params.get('state');

// state 검증 (CSRF 방지)
const savedState = sessionStorage.getItem('oauth_state');
if (returnedState !== savedState) {
  throw new Error('State mismatch - possible CSRF attack');
}
sessionStorage.removeItem('oauth_state');

const codeVerifier = sessionStorage.getItem('oauth_code_verifier');
sessionStorage.removeItem('oauth_code_verifier');

// 동의 거부 등으로 code가 없는 경우 처리
if (error === 'access_denied') {
  showMessage('로그인을 취소했습니다.');
} else if (error || !code) {
  showMessage('로그인에 실패했습니다.');
} else {
  // 토큰 교환은 앱의 백엔드가 수행합니다.
  await fetch('/api/auth/datagsm/callback', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ code, codeVerifier }),
  });
}
```
